Finanças mais claras, sob seu controle

O Trokim é um assistente financeiro pessoal para Android. Reúne lançamentos de extratos e faturas para ajudar você a compreender receitas, despesas e hábitos de consumo — com processamento local e orientações apoiadas em materiais do BCB, CVM e CFPB.

  

Telas reais do aplicativo com dados sintéticos. Resumo financeiro e importação de extratos.

Engenharia por trás da experiência

  • Cálculos determinísticos: totais e indicadores financeiros são computados em Python; a LLM atua na explicação.
  • Respostas com evidências: busca híbrida semântica e textual, citações e abstenção quando falta evidência ou o tema está fora do escopo.
  • Privacidade por arquitetura: API na máquina do usuário, embeddings locais e inferência via Ollama. Provedores de nuvem são opcionais e enviam conteúdo ao serviço escolhido.
  • Evolução com rastreabilidade: backend em camadas, provedores de LLM desacoplados, prompts versionados, testes e decisões registradas em ADRs.

Stack: Flutter · Dart · Python 3.12+ · FastAPI · Pydantic · SQLite / sqlite-vec · FastEmbed · LiteLLM / Ollama.

Execute localmente

Pré-requisitos: Python 3.12+, uv e, para o app Android, Flutter, JDK e Android SDK nas versões documentadas.

git clone https://github.com/moonshinerd/trokim.git
cd trokim
make setup
make api-run

Em outro terminal, na raiz do projeto:

make mobile-run

A API oferece Swagger e health check. O emulador Android usa http://10.0.2.2:8000/v1.

Para respostas generativas, configure o Ollama conforme o guia de uso. A primeira consulta RAG pode baixar o modelo de embeddings. Use make synthetic-data para gerar arquivos de demonstração; configuração, conexão com aparelho físico e importação estão no guia.

Estágio atual: protótipo em desenvolvimento, voltado à execução local. Os lançamentos importados ficam na memória da API e são perdidos ao reiniciá-la; a base vetorial usa SQLite. Persistência financeira e operação com múltiplas instâncias exigem evolução da arquitetura. Veja o planejamento e a ADR de importação.

Qualidade e contribuição

O CI verifica API, pesquisa, aplicativo e documentação. Para validar alterações:

make lint          # Ruff e análise Flutter, quando instalado
make test          # API, pesquisa e benchmark RAG
make docs-build    # Documentação em modo estrito
(cd mobile && flutter test)

Consulte as issues, siga as regras de contribuição e abra uma PR vinculada à issue, com testes e documentação atualizados. Utilize somente dados sintéticos nos exemplos e testes.
